# 게임 글 문체 기준 (10월 9일 만든 사람 요청)

화면에 보이는 모든 글(도움말, 설명 창, 장비 · 스킬 · 소모품 · 깨달음 설명, 적 · 보스 소개, 수련장, 업데이트 내역, 버튼과 알림)에 적용한다. 목표는 **AI가 쓴 티를 완전히 지우고, 그 분야 전문가인 한국인이 직접 쓴 글처럼** 만드는 것이다. 일반 플레이어가 읽고 바로 알 수 있는 짧고 확실한 설명이 우선이다.

## 만든 사람이 정한 금지 사항

1. **번역투 금지.** "~에 관하여", "~를 통해", "~에 대해 말하자면", "결론적으로", "요약하자면", "뿐만 아니라 ~도", "~할 수 있다" 같은 영어 직역투를 쓰지 않는다.
2. **기계적 대칭 · 병렬 구조 금지.** "첫째, 둘째, 셋째"나 억지로 세 가지씩 늘어놓는 구조를 피한다.
3. **과하게 친절하거나 웅장한 서두 · 결론 금지.** "흥미로운 질문이네요!", "~라는 점을 명심해야 합니다" 같은 상투 멘트를 지운다.
4. **문장 길이를 맞추지 않는다.** 짧은 문장과 긴 문장을 자연스럽게 섞는다.
5. **원래 글이 전달하는 정보와 논리를 바꾸지 않는다.** 숫자, 조건, 예외, 용어는 그대로 둔다.

## 쓰는 법

- **요약이 먼저다.** 설명 첫 문장이 핵심이다. 세부는 그 뒤에 짧게 붙이고, 필요 없으면 뺀다. 한 문장에 한 가지만 말한다.
- **짧게.** 같은 말을 되풀이하지 않는다. 한 칸의 설명은 보통 한두 문장이다. 길어지면 항목으로 나누지 말고 줄인다.
- **쉬운 말.** 일반 플레이어가 모르는 개발 용어(키 이름, 내부 변수, "수치 가설" 같은 말)를 쓰지 않는다. 게임 용어(붕괴, 보호, 약화, 쿨타임 등)는 기존 표기를 그대로 쓴다.
- **직접 말한다.** "~할 수 있습니다" 대신 "~합니다", "~됩니다"로 쓴다. 정말 선택 사항일 때만 "~할 수 있습니다"를 쓴다. 피동("~되어집니다", "~게 됩니다")과 "~것입니다" 말투를 줄인다.
- **명사를 늘어놓지 않는다.** "사용에 대한 제한이 존재합니다" 대신 "쓸 수 없습니다".
- **합니다체.** 버튼은 짧은 동작형("사기", "닫기"). 전투 기록은 현재형 서술 뒤에 수치.
- **쓰지 않는 것:** 줄표(—)로 문장 잇기, 괄호 부연 겹치기, 느낌표, "이(가)" 같은 괄호 조사(조사는 fixJosa가 자동으로 고른다). 분위기 한 줄(lore)은 규칙 문장과 섞지 않는다.
- **보스 · 강적의 기믹과 대처법은 쓰지 않는다.** 숨겨진 직업의 이름 · 규칙 · 해금 조건도 쓰지 않는다("숨겨진 직업"으로만).

## 예

- 전: "방어를 선택하면 해당 차례 동안 받는 피해를 줄일 수 있으며, 이를 통해 생존력을 높일 수 있습니다."
- 후: "방어하면 이번 차례에 받는 피해가 절반으로 줄어듭니다."

- 전: "스태미나는 행동을 수행하는 데 필요한 자원이며, 부족할 경우 일부 행동을 사용할 수 없게 됩니다."
- 후: "스태미나가 모자라면 그 행동은 쓸 수 없습니다. 방어하거나 쉬면 차오릅니다."

## 점검

- `node tools/textnum.js <파일> [--base 커밋]`: 고치기 전(기본은 HEAD) 대비 **문장 속 숫자가 줄마다 같은지** 본다. 다르면 정보가 바뀌었을 수 있으니 줄을 열어 확인한다(의도한 수정이면 이유를 기록한다).
- 문장을 만드는 코드(`skHead` · `skBody` 등)를 고쳤으면 `node tools/skillscore.js`와 `node tools/docsync.js --check`가 그대로여야 한다.
- 고친 뒤 `PYTHONIOENCODING=utf-8 python tools/smoke_site.py 06a2`, `node tools/itemcheck.js`, `DGDIR=06a2 node tools/item3check.js`, `DGDIR=06a2 node tools/ch3check.js`가 그대로 통과해야 한다.
- 새 문장을 눈으로 훑어 위 금지 사항에 걸리는 것이 없는지 본다("~를 통해", "~에 대해", "결론적으로", "~할 수 있", "~것입니다", 문장마다 같은 길이).
