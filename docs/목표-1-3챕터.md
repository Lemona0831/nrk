# 목표: 1~3챕터 완성 (10월 5일 만든 사람)

현재 저장소와 docs의 모든 관련 자료를 읽고, 실제로 구현된 게임을 기준으로 1~3챕터를 완성하라. 기존 기획서는 구판의 내용을 포함하므로 그대로 따르지 않는다. 구현, 최신 문서, 작업 기록, 이전 결정이 충돌하면 각각의 시점과 근거를 확인하고 현행 규칙을 확정한다.

이 목표는 문서만 만드는 작업이 아니다. 기획 → 반례 검토 → 구현 → 자동 검증 → 직접 플레이 및 사람 플레이에서 확인할 항목 정리 → 문서 갱신을 반복하는 장기 작업이다. 범위가 커도 임의로 축소하거나 일부만 끝내고 전체 목표를 완료했다고 선언하지 말라. 각 단계의 진행 상황과 미해결 위험을 남기고 다음 작업으로 이어 가라.

작업할 사이트는 06a2. 추후 메인 사이트로 올릴 예정인 테스트용 스킬 재설계 및 전체 재개편을 이어나가던 사이트에서 실시한다.

## 최종 목표

플레이어가 어려운 던전을 공략하면서 직업마다 다른 방식으로 승리하고, 스킬 트리·능력치·장비·소모품을 조합해 빌드를 만드는 게임을 완성한다.

- 기존 공개 직업인 암살자와 파수꾼을 포함하여, 제작 중인 사냥꾼과 남은 공개 직업 3개까지 공개 직업 총 6개를 완성한다.
- 숨겨진 직업 3개를 설계하고 완성한다.
- 모든 직업과 주요 갈래에 1~3챕터를 통과할 수 있는 검증된 승리 플랜을 마련한다.
- 1챕터를 다시 검증·조정하고, 현재 규칙에 맞는 2·3챕터를 완성한다.
- 2챕터 장비 200종, 3챕터 장비 200종을 영웅·전설 등급을 포함해 설계·구현한다.
- 챕터별 소모품, 적과 보스, 경로, 상점, 도박, 패시브, 가혹 모드, 반복 플레이 구조를 하나의 경제와 난이도 체계로 연결한다.
- 모든 변경을 반영한 현행 통합 기획서와 직업별 상세 기획서를 작성한다.

설정된 도구와 모델을 장기 작업의 설계·구현·검토에 적극 활용하되, 긴 추론이나 많은 자동 테스트 자체를 품질의 증거로 취급하지 말라.

## 중요한 설계의 네 단계

각 중요한 설계는 다음 네 단계를 분리한다.

- **설계:** 의도하는 플레이 경험, 규칙, 수치 가설, 다른 시스템과의 관계를 작성한다.
- **반례 검토:** 그 설계를 깨뜨리는 빌드, 행동 순서, 적 조합, 아이템 조합, 무한 반복, 사실상 쓸모없는 선택지를 찾는다. 설계한 관점과 다른 관점에서 다시 읽고 반대 의견을 기록한다.
- **구현·측정:** 실제 게임에서 작동하게 만들고, 고정 시드와 재현 가능한 조건으로 검증한다.
- **재판단:** 측정값과 플레이 감각이 다르면 원인을 조사한다. 목표 수치를 맞추기 위해 테스트 상황이나 테스터의 판단만 유리하게 바꾸지 않는다.

독립된 검토 역할이나 병렬 작업을 사용할 수 있다면 직업 설계, 적·보스 설계, 경제·아이템, UI·UX, QA를 나누어 검토한다. 실제로 수행하지 않은 회의·검토·플레이 테스트를 수행한 것처럼 기록하지 말라. 서로 다른 판단이 나오면 근거와 최종 결정을 남긴다.

한 번에 모든 파일을 만들지 말고, 작동하는 단계별 결과를 남긴다. 각 단계에서 구현과 문서가 일치하는지 확인한 다음 다음 단계로 진행한다.

## 1단계 — 현행 게임 조사와 기준 확정

작업을 시작할 때 저장소와 docs를 조사하여 다음을 작성한다.

- 현행 규칙, 이미 구현된 콘텐츠, 아직 기획에만 있는 콘텐츠의 목록
- 구판 기획서와 최신 구현·문서 사이의 차이
- 직업·스킬·능력치·행동 순서·상태 효과·아이템·소모품·던전·보스·상점·저장 데이터의 연결 관계
- 현재 자동 테스터가 실제 사람의 판단을 잘 흉내 내는 부분과 그렇지 못한 부분
- 기존 측정값 가운데 규칙 변경으로 무효가 된 값
- 이후 변경 시 함께 수정해야 할 화면 설명, 도움말, 저장본 변환 및 테스트 도구

충돌을 발견하면 현행 기준과 이유를 기록한다. 불확실한 사항은 추측을 사실처럼 적지 말고 실험 또는 검토 항목으로 남긴다.

## 2단계 — 1챕터 완성도 검증과 조정

새 챕터를 확장하기 전에 1챕터를 현재 직업·적 행동·소모품·전리품 규칙으로 다시 검증한다.

1챕터는 어렵지만 배울 수 있어야 한다. 플레이어가 초반부터 적의 예고, 경로의 위험, 자원 사용, 직업의 핵심 행동을 읽고 "내 판단으로 살았다"는 경험을 적어도 한 번 할 수 있도록 설계한다. 패배했을 때는 원인과 다음 시도에서 바꿀 선택이 보여야 한다. 후속 챕터의 적·보스·세계관에도 개연성을 부여해야 한다.

다음 항목을 따로 확인한다.

- 첫 전투부터 보스까지의 난이도 곡선과 첫 사망 지점
- 각 직업의 첫 유효한 판단, 첫 위기, 위기에서 회복할 기회
- 적의 예고를 보고 대응할 차례가 실제로 보장되는지
- 경로 선택의 위험과 보상이 읽히는지
- 일반 전투, 강적, 보스에서 각 직업의 승리 플랜이 작동하는지
- 전리품과 상점이 빌드의 방향을 바꿀 만큼 의미 있는지
- 특정 직업·갈래가 초반에 필수 선택이 되거나 사실상 함정이 되는지
- 자동 테스터 승률과 사람의 체감 난이도가 다른 이유

문제는 적 피해량이나 플레이어 체력만 바꾸어 덮지 말고, 적의 행동 빈도·예고·전투 길이·보상·회복 기회까지 함께 검토한다.

## 3단계 — 직업별 상세 기획서 작성

8개 직업 모두 각각 독립된 상세 기획서를 작성한다. 기존 암살자·파수꾼 문서도 현행 구현에 맞게 갱신한다. 숨겨진 직업의 정보가 일반 플레이어에게 노출되지 않도록 공개 문서·화면과 내부 기획 자료를 구분한다.

각 직업 문서는 최소한 다음 항목을 포함한다.

### A. 직업 정체성

- 한 문장으로 설명한 전투 경험과 핵심 판타지
- 다른 7개 직업과 구별되는 행동 방식
- 플레이어가 매 차례 판단할 대상과 성공했을 때 느끼는 보상
- 의도한 숙련 난도와 1챕터에서 가르칠 최소 규칙

### B. 핵심 규칙과 전투 리듬

- 기본 공격, 강공격, 시작 스킬, 고유 자원 또는 상태
- 행동 순서, 추가 행동, 쿨타임, 지속 시간, 중첩, 상한의 정확한 처리 순서
- 통상적인 2~4라운드 행동 예시와 예외 상황
- 적이 하나일 때·여럿일 때·후열에 있을 때의 플레이 변화
- 한 번의 실수가 어떤 손해를 만들고, 어떻게 수습할 수 있는지
- 다른 직업도 같은 능력을 얻는 아이템이 있을 때 직업 정체성이 유지되는지

### C. 전체 스킬 트리

- 현재 게임의 트리 구조를 기준으로 모든 칸의 이름, 해금 위치, 비용, 행동 종류, 대상, 쿨타임, 효과, 수치와 설명 문장
- 갈래와 기둥별 역할, 초반·중반·후반에 투자할 이유
- 각 칸을 언제 쓰는지, 앞선 칸과 무엇이 다른지
- 서로 섞었을 때의 이득과 한 갈래에 집중했을 때의 이득·한계
- 사실상 같은 버튼을 숫자만 높여 반복하는 칸, 상위 칸에 완전히 밀려 버리는 칸의 점검
- 1챕터에서 실제로 얻는 포인트만으로 성립하는 최소 빌드와 2~3챕터 확장 빌드

### D. 승리 플랜과 약점

- 각 갈래의 일반 전투·강적·각 챕터 보스 상대 승리 플랜
- 필수 행동 순서, 필요한 자원, 장착 가능한 실제 스킬 조합
- 승리 플랜이 실패하는 조건과 그때 선택할 수 있는 대응
- 지원형 적, 무리, 거구, 후열, 강타, 지속 피해 등 주요 상황에서의 강약
- 약점이 수치표에만 존재하는지, 플레이에서도 실제로 느껴지는지
- 장비 운이 나쁘거나 특정 희귀 아이템이 없어도 기본 승리 플랜이 유지되는지

"이론상 이길 수 있다"는 문장만으로 통과시키지 말라. 각 직업·갈래의 승리 플랜을 실제 장착 제한과 해당 챕터의 아이템 획득 조건에서 실행해 검증한다.

### E. 상호작용·악용 가능성 점검

추가 행동 중 추가 행동 재생성, 쿨타임 단축 반복, 무한 회피·반격, 자원 무한 생성, 상태 중첩, 행동 차단 연쇄, 보스 기믹 건너뛰기, 장비·소모품 결합으로 인한 과도한 폭발력 등을 검토한다. 문제가 없다고 판단한 경우에도 확인한 조건을 적는다.

### F. 화면과 검증

- 플레이어가 지금 가진 자원·상태·표적·예고·다음 행동의 효과를 어디서 읽는지
- 버튼에 필요한 미리보기와 실제 결과의 일치 여부
- 자동 테스트 결과, 직접 플레이에서 볼 질문, 사람 테스트에서 확인할 질문
- 확정된 규칙, 실험 중인 수치, 남은 위험을 구분한 최신 상태

### 사냥꾼

사냥꾼은 현재 논의 중인 연속 두 행동을 핵심 가설로 검증한다. 기존 순서 변경형 가속과 새 추가 행동을 명확히 구분하고, 한 라운드의 행동 상한·쿨타임·지속 효과·추가 행동 중 재발동을 정의한다. 암살자보다 낮은 한 방 피해만 확인하지 말고, 적이 행동하기 전에 처치하거나 끊는 빈도까지 비교한다. 초반의 적은 포인트로도 기동과 저격 또는 연사를 섞는 재미가 나는지 확인한다.

## 4단계 — 2·3챕터 던전과 적·보스

기존 챕터 콘셉트를 검토하되 현행 게임의 직업과 시스템에 맞춰 다시 설계한다. 2챕터는 1챕터에서 배운 대응을 새로운 적 조합과 행동으로 변주하고, 3챕터는 그 판단들을 더 복합적으로 요구한다.

챕터마다 다음을 정한다.

- 장소·서사·시각적 분위기와 앞뒤 챕터의 연결
- 층과 경로 구조, 일반 전투·매복·강적·상점·이벤트의 분포
- 적의 역할, 행동 주기, 예고, 대응법, 다른 적과의 조합
- 처음 등장할 때 가르치는 방식과 이후 변주의 방식
- 보스의 페이즈, 예고, 직업마다 가능한 공략법
- 패배 원인을 읽기 어렵거나 특정 직업의 수단만 막는 패턴의 점검
- 난이도 상승에 맞는 회복·골드·소모품·장비 공급

모든 보스는 8개 직업 각각에 서로 다른 장점은 허용하되 실제 승리 가능한 길을 제공해야 한다. 한 직업이 보스를 이기기 위해 특정 전설 장비 하나를 반드시 얻어야 하는 구조는 피한다.

## 5단계 — 장비·소모품·경제

2챕터 장비 200종, 3챕터 장비 200종을 작성하고 구현한다. 각 장비에는 고유 식별자, 이름, 등급, 등장 챕터와 획득처, 효과와 수치, 주요 사용 직업·빌드, 설계 의도, 예상 성능, 상점 가치 및 악용 가능성을 기록한다.

종류만 채우는 수치 변형을 최소화한다. 같은 등급 안에서도 선택 이유를 구별하고, 영웅·전설 등급은 희귀성에 맞는 특별한 조합을 제공하되 필수 승리 수단이 되지 않게 한다. 획득 확률은 실제 플레이 횟수에서 체감 가능한지 계산하고, 희귀 아이템이 없어도 던전을 공략할 수 있게 한다.

소모품은 챕터의 적과 환경에 맞게 설계한다. 현재의 사용 시간·가방 칸·상점 구매·전리품 규칙을 확인하고, 한 전투에서 무제한 사용하거나 경제를 우회하는 조합을 방지한다. 능력치, 패시브, 장비, 소모품의 효과가 겹칠 때 처리 순서와 상한도 문서화한다.

상점과 도박 시스템은 골드의 공급·소비, 실패 시 손실, 희귀 장비의 가치, 반복 가능한 이익을 함께 검토한다. 도박이 언제나 최선이거나 언제나 손해인 선택이 되지 않도록 한다.

## 6단계 — 가혹 모드와 반복 플레이

가혹 모드는 현재 일반 모드의 경로 선택을 바탕으로 별도 설계한다. 기존 샛길도 일반 모드의 평범한 길에 준하는 위험을 갖고, 다른 경로에는 강적의 빈도와 보상을 늘린다. 적과 보스의 피해는 일반 모드 대비 약 1.3~1.5배를 목표로 검증한다.

배율을 일괄 적용한 결과 특정 직업에 대응할 차례가 사라지거나 피할 수 없는 피해로 즉사한다면, 그 원인을 조사하고 행동 예고·빈도·회복·보상을 함께 조정한다. 가혹 모드의 차이를 시작 전에 플레이어가 알 수 있게 보여 준다.

3챕터 이후에도 플레이할 이유가 있도록 챕터 반복·재도전 구조를 복수의 안으로 설계한다. 반복할 때 바뀌는 적·경로·보상·빌드 목표, 진행 기록, 난이도 상승, 새 플레이어와 숙련자의 진입 방식을 비교한다. 가장 적절한 안을 실제 게임에 적용하고 플레이 결과로 재검토한다.

## 7단계 — 검증 기준

직업·갈래·장비·소모품·적 조합·경로·챕터·난이도·시드를 아우르는 누적 10,000회 이상의 재현 가능한 자동 전투 및 던전 테스트를 수행한다. 총 횟수만 보고하지 말고, 어떤 조건에 몇 회를 배정했는지와 빠진 조건을 기록한다. 일부 조건만 반복한 10,000회를 전체 게임 검증으로 주장하지 말라.

다음 결과를 직업과 갈래별로 분리해 본다.

- 층별 도달률, 완주율, 보스 도달률과 보스 승률
- 사망 원인과 예고 후 대응 가능 여부
- 받은 피해, 회복·소모품·골드의 수급과 사용
- 전투 길이, 행동 종류, 추가 행동과 행동 차단 횟수
- 실제 장착한 스킬·장비의 빈도와 사용하지 않는 칸
- 특정 희귀 아이템이나 특정 빌드가 결과를 지배하는지
- 일반 모드와 가혹 모드의 위험·보상 차이

자동 테스터의 전략이 바뀌면 이전 결과와 바로 비교하지 말고, 무엇이 달라졌는지 기록하고 기준 결과를 다시 잰다. 테스트에 쓰지 않은 시드와 조합으로도 결과를 확인한다. 직접 플레이와 사람 플레이에서는 승률 외에 규칙 이해, 선택의 이유, 실수의 납득 가능성, 다시 도전하고 싶은 이유를 확인한다.

수치 기준을 충족해도 플레이가 단조롭거나 승리 플랜이 한 가지로 고정되면 설계를 다시 본다. 반대로 수치 기준에서 조금 벗어나도 고유한 재미와 공정한 대응이 확인되면 근거를 남겨 판단한다.

## 문서와 완료 조건

작업 내내 직업별 기획서 8개, 챕터별 설계, 장비·소모품 목록, 시스템 규칙, 테스트 결과를 최신 상태로 유지한다. 마지막에는 구판 기획서를 대체할 현행 통합 기획서를 작성한다. 현행 수치와 이전 실험값을 한 표에 섞지 말고 날짜·버전·적용 상태를 표시한다.

완료를 선언하기 전에 이 목표의 모든 항목을 실제 파일, 실행 결과, 게임 화면, 테스트 기록과 대조하라. 특히 다음이 증명되어야 한다.

- 8개 직업의 독립된 기획서와 실제 구현이 일치한다.
- 모든 직업과 주요 갈래에 1~3챕터의 실행 가능한 승리 플랜이 있다.
- 1챕터의 학습·난이도·보스 흐름을 다시 검증했다.
- 2·3챕터의 적·보스·보상과 각 200종 장비가 실제로 작동한다.
- 소모품, 상점, 도박, 패시브, 가혹 모드, 반복 플레이가 연결되어 있다.
- 10,000회 이상의 테스트 범위와 결과를 재현할 수 있다.
- 화면 설명, 도움말, 저장 데이터 처리, 최신 문서가 실제 게임과 일치한다.
- 구판을 대체하는 현행 통합 기획서가 있다(현행 수치와 실험값을 섞지 않고 날짜·버전·적용 상태 표시).
- UI/UX가 시장 조사를 통해 기획서.md에서 드러났던 여타 게임들의 UI/UX를 따랐는가를 판단하고, 가독성 및 비주얼이 개선되었음을 객관적으로 증명해 낼 수 있다. (10월 5일 만든 사람 추가)
- 웹 접근성 4대 원칙(KWCAG 2.2)을 따랐으며 W3C 표준 가이드라인을 준수했다. (10월 5일 만든 사람 추가)

증거가 부족한 항목은 완료로 표시하지 말고 남은 작업과 위험을 명시한 뒤 계속 진행하라.
