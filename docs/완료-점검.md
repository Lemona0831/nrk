# 완료 조건 점검 (docs/목표-1-3챕터.md 대조, 10월 8일, 0.6a.2-68)

- **읽는 법:** 완료 조건을 한 줄씩 실제 파일 · 실행 결과와 맞춘다. **충족**은 증거가 있다는 뜻이고, **부분**은 증거가 일부뿐이거나 기준 일부가 미달이며, **사람 필요**는 자동 도구로 증명할 수 없는 것이다. 완료 선언이 아니라 남은 일의 목록이다.
- **전체 판정:** 구현과 자동 검증의 틀은 갖췄지만, 아래 "부분 · 사람 필요" 항목이 남아 있어 **목표 전체는 아직 완료가 아니다.**

## 해야 할 일 (사람이 필요한 것)

1. **사람 플레이**: docs/검증-계획.md 5절의 질문(규칙 이해 · 선택의 이유 · 실수의 납득 · 다시 하고 싶은 이유 · 해금 · 보스)에 답할 기록. 위 2 · 4 · 5번 "사람 필요"의 근거가 된다.
2. **KWCAG 원문 대조 · 화면 낭독기 시험 · W3C 검증기**(10번).
3. **만든 사람 결정** 55건(docs/만든사람-결정.md). 특히 7(2챕터 완주 목표) · 43(0.6배 기준 세기) · 44(가혹 수치) · 50(테스터 규칙으로 얻은 사냥꾼 승률) · 53~55(표식 보상 · 강도).

## 자동 도구로 더 할 수 있는 일 (이번에 하지 않은 것)

- 직업 사이 완주 차이를 ±5%p로 줄이기(파수꾼 13% 대 암살자 · 해금 2 5%).
- 던전에서 약한 갈래(5~8%) 원인 가르기: 50상황과 던전의 차이가 자원 흐름인지 테스터 사용법인지.
- 가혹 모드를 설계 목표(일반의 40~60%)에 가깝게.
- 설문 단계 옛 저장본 시험.

사람 플레이를 시키는 법과 기록 받는 법은 docs/사람-플레이-안내.md에 정리했다.
