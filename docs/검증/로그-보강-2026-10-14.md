# 판 기록 보강 — 2026-10-14

[9직업 재검토](../제안/9직업-전투성장-재검토-2026-10-14.md) §9의 P0(L-1·L-2) 적용 기록이다. **게임 규칙·수치는 바뀌지 않았다.** 기록에 남는 정보만 늘렸다. 이후 변경의 전후를 같은 표로 비교하기 위한 준비다.

## 바뀐 것

| 기록 | 어디에 | 무엇을 남기나 |
| --- | --- | --- |
| 전투 방 기록 | 방 기록(`rooms[]`)의 전투 방 | `rev`(그 전투를 한 배포의 식별자 앞 12자), `herbIn`·`breadIn`(입장 직전 약초·빵 개수), `goldIn`, `bagIn`(가방 칸 수) |
| 지난 상점 방문 | 판 기록의 `shopHist[]` | 챕터를 넘어가도 이전 챕터 상점의 진열·소모품 진열·구매·판매 기록을 지우지 않고 보관 |
| 현재 상점 | 판 기록의 `shop` | 소모품 진열(`cons`)을 추가 |

- 이전에는 상점 기록이 다음 챕터 상점이 열릴 때 덮어써져 마지막 방문만 남았다. 소모품 진열은 아예 저장되지 않았다.
- 제단·이벤트 같은 비전투 방의 기록은 다른 코드가 만들므로 이번에는 건드리지 않았다.
- 이미 쌓인 기록에는 새 필드가 없다. 새로 하는 전투부터 남는다.

## 고쳐지지 않은 것

- 입장 시 생명력 플라스크 재고(`flasksIn`)는 이미 기록되지만 일부 오래된 판에는 필드가 없다. 새 판에서는 채워진다.
- 행동별 생명력은 이미 `act.hp`에 있다.
- 개인 기록 JSON의 크기는 방마다 숫자 4개와 짧은 문자열 하나가 늘고, 상점 방문마다 진열 12개 안팎이 늘어난다. 저장 용량 영향은 실사용에서 확인해야 한다(모바일 저장 용량 보완은 [별도 기록](모바일-저장실패-보완-2026-10-13.md)).

## 검증

- `DGDIR=. node tools/log-fields-check.js`와 `DGDIR=06a2 node tools/log-fields-check.js`: 세 직업의 자동 던전 진행에서 전투 방 기록에 새 필드가 모두 숫자·문자열로 들어가고, 상점을 열어 둔 채 다음 챕터로 넘어갈 때 `shopHist`에 진열 6개·소모품 진열 6개와 구매 기록이 보관되며 현재 상점이 비워지는 것을 확인했다. 루트·개발본 모두 통과.
- `node tools/admin-details-check.js`: 장비·트리 스냅샷·과거 기록·동명이인·직업 렌더 통과(루트·개발본).
- `node tools/stamp-release.js --check` 통과.
- **확인하지 못한 것:** 실제 브라우저에서 `rev`가 배포 식별자로 채워지는지(자동 시험은 문서가 없는 환경이라 빈 문자열), 실제 계정 동기화에 새 필드가 올라가는지, 모바일 저장 용량 영향.
- 플레이어용 업데이트 내역에는 넣지 않았다. 화면·규칙이 바뀌지 않은 기록 변경이며 [문체 기준](../문체-기준.md)의 "개인 기록·운영 변경은 넣지 않는다"를 따랐다.
