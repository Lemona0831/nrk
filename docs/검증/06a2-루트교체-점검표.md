## (b) 교체 절차

한 사람이 한 번에 한다. 각 단계 끝에 아래 확인을 한다.

1. 저장소를 main 최신으로 맞추고 `git status`가 깨끗한지 본다. 직전 루트 커밋을 적어 둔다: `git log -1 --format=%H -- index.html` (되돌릴 때 쓴다).
2. 사본을 새로 만든다: `python tools/release062.py` → `rehearse062.py` 통과 확인.
3. 옛 루트를 한 곳에 보존한다. 이미 git에 있으므로 별도 복사는 필요 없다. 다만 **옛 0.6a를 계속 보여 줄지**를 정한다. 선택지: (가) 보존하지 않고 git 기록에만 둠, (나) `b06a/`처럼 한 폴더에 복사해 둠(b05/ 방식, 고치지 않음). 추천은 (나): 이관 선택지 1에서 지인이 옛 판 결과를 볼 곳이 필요하다.
4. 루트에서 바꿀 파일:
   - `index.html`: 사본의 `index.html`로 교체
   - `data/`: 통째로 교체(사본 `data/`). 0.6a의 `data/` 파일 가운데 06a2에 없는 것은 지워진다
   - `js/`, `css/`: 새로 생긴다
   - `audio/`: 사본 `audio/`로(ch3_* 세 곡이 더해진다). 기존 파일은 이름이 같고 내용이 같으니 덮어도 된다
   - `privacy.html`: 그대로 둔다(변경 없음)
   - `config.js`: **사본의 빈 config.js를 복사하면 안 된다.** 루트의 진짜 config.js를 그대로 둔다. 만든 사람이 관리하는 파일이다
5. 지우거나 보존할 옛 루트 파일: `data/` 안에서 06a2에 없는 파일은 교체 때 사라진다(git에 남음). `06a2/` 폴더는 교체 뒤에도 둘지(시험판 주소가 계속 열림, 키 `nrk_062_v1`로 같은 키를 쓰게 되므로 같은 기록을 서로 덮을 수 있다) 정한다. 추천: 교체 직후 `06a2/`는 그대로 두고, 일주일쯤 뒤 지운다(미리보기 주소만 쓰지 않도록 안내). `next/`와 `b05/`는 건드리지 않는다.
6. 커밋 메시지는 한국어 영어 무관, 예: `Release 06a2 to root (rehearsed)`. 푸시하면 1~2분 뒤 Pages가 바뀐다.
7. 반영 확인: 푸시 뒤 `python tools/smoke_site.py .`(루트), 브라우저에서 https://lemona0831.github.io/nrk/ 를 강력 새로고침해 제목 · 버전 · 곡 재생(ch3 곡 포함)을 본다. Pages 배포 상태는 `gh run list --limit 3` 또는 저장소 Actions 탭.
8. CLAUDE.md를 (d)대로 고친다.

**되돌리는 법** (루트 커밋이 푸시된 뒤): 직전 루트 커밋을 `<OLD>`라고 하면
`git revert <교체 커밋>` 한 번이 가장 안전하다(기록이 남고 푸시 한 번으로 끝난다).
교체 커밋 하나에 루트 변경만 담았다면 위 한 줄이면 충분하다. 커밋을 여럿으로 나눴다면
`git checkout <OLD> -- index.html data audio` 뒤 `git rm -r js css`(새로 생긴 폴더)로 지우고 커밋한다.
`git reset --hard` · 강제 푸시는 쓰지 않는다. 브라우저 쪽 기록(키 `nrk_062_v1`)은 돌려도 남으므로 지인에게 문제가 없다.

## (c) 지인 기록 · 랭킹 · 저장 키 이관 선택지

지금 키와 경로는 0.6a(루트)와 06a2가 다르다.

| | 0.6a(루트) | 06a2 |
| --- | --- | --- |
| 브라우저 저장 키 | `nrk_06_v1` | `nrk_062_v1` |
| 판 기록 · 상황 · 설문 | `runs6` · `scen6` · `survey6` | `runs62` · `scen62` · `survey62` |
| 기록판 칸 · 랭킹 칸 | `best6` · `rank6` | `best62` · `rank62` |
| 계정 문서 | `playtest/(uid)` | 같은 문서(이름 · 판 수), 해금 `unl62` · 목표 `goals62` |

계정(익명 uid, 구글 로그인)은 같으므로 로그인은 이어진다. 갈리는 것은 **캐릭터 · 진행 중 판 · 기록판 · 랭킹**이다.

**선택지 1: 새 시작 (키 그대로)**
- 지인의 06a2 진행은 06a2에서 만든 것이 그대로 남고, 루트에 들어온 사람은 06a2 키를 처음 쓰는 것이면 빈 상태로 시작한다. 옛 0.6a 기록은 Supabase에 남아 있고(지우지 않는다) 결과 보기에서는 읽힌다.
- 위험: 지인이 "기록이 사라졌다"고 느낀다. 0.6a 캐릭터는 직업 체계(스킬 · 트리)가 달라 이어 쓸 수 없다는 점은 이관해도 같다.
- 작업량: 없음. 안내문에 알리면 된다.

**선택지 2: 옛 기록을 06a2 키로 복사하는 한 번짜리 이관 스크립트**
- 하는 일: 브라우저 `nrk_06_v1`의 기록(완료한 판 `runs`, 이름, 설정)을 `nrk_062_v1`로 복사하고, Supabase의 `runs6` → `runs62`, `best6` → `best62`, `rank6` → `rank62`를 복사한다. 진행 중 판과 캐릭터(직업 · 스킬)는 옮기지 않는다(구조가 다르다: v2 직업은 마나 없이 쿨타임 스킬과 트리를 쓰고 `TREE2`가 다르다).
- 위험: (1) 이관된 `runs`의 `build` · `skills`가 06a2에 없는 값이라 기록 화면 · 해금 · 목표 셈(`goalsRecord`)이 틀릴 수 있다. (2) 랭킹 `rank6`의 점수 기준(1챕터만)이 06a2의 챕터 · 모드 기준과 달라 순위가 섞인다. (3) 보안 규칙상 자기 uid 문서만 쓸 수 있어 지인마다 브라우저에서 스크립트가 돌아야 한다(만든 사람이 모아 줄 수 없다). (4) 한 번짜리라 실수 시 되돌리기 어렵다.
- 작업량: 스크립트 + 옛 기록 형식을 06a2 `treeFix` · `dgFix`로 확인하는 시험 + 지인 안내. 크게 한나절 이상. 06a2 `resumeRun`의 fix가 옛 저장본을 열 수 있는지(`tools/savecheck.js`와 같은 방식)도 먼저 봐야 한다.

**추천: 선택지 1.** 까닭은 옛 캐릭터가 06a2에서 쓸모없고, 기록 화면 · 랭킹이 기준이 달라 섞이면 오히려 읽기 어렵다. 옛 기록은 저장소에 남고 `b06a/`(위 3단계 (나))나 결과 보기에서 읽는다. 지인이 옛 판을 보고 싶어 하는 경우만 읽기 전용 복사(옛 `runs6`를 결과 보기에서 계속 보이게 하는 것)를 따로 생각한다.

## (e) 구글 로그인 Redirect URLs (만든 사람이 직접 할 일)

- 06a2 주소(`…/nrk/06a2/`)는 교체 뒤에도 시험판을 남기면 그대로 둔다. 지우면 06a2 주소의 구글 로그인이 안 된다
