# 쓰러진 캐릭터가 되살아나던 오류 (0.6a.2-97, 10월 10일)

## 증상

캐릭터가 쓰러진 뒤 설문을 건너뛰고 타이틀로 돌아와, 메뉴의 스킬 트리(남은 포인트 표시)에서 칸을 열고 나오면 타이틀에 이어하기가 생기고 죽은 캐릭터가 던전 앞에서 다시 시작할 수 있었습니다.

## 원인 (재현으로 확정)

쓰러짐을 확정하는 `battleContinue`는 `run.result = 'lose'`로 두고 `clearCur()`로 이어하기 저장본을 지웁니다. 하지만 `run.endedAt`은 설문을 마치는 `finishSurvey`에서만 붙습니다. 그 사이의 판은 "죽었는데 끝나지 않은 판"이었고, 코드 곳곳이 끝남을 `endedAt`만 보고 판단했습니다.

- 메뉴(`menuItems`)가 `G.run.tree`만 보고 스킬 트리를 보여 주었습니다.
- 트리 칸 열기(`tunlock`)와 장착(`tequip`)은 `treeCanEdit`(전투 중이 아니면 허용)만 보고, 끝에서 `saveCur()`를 불렀습니다.
- `saveCur`는 `endedAt`이 없으면 `G.run` 전체를 `G.data.cur`에 넣었고, 타이틀이 그것을 이어하기로 보여 주었습니다.

가설대로 (a) 메뉴 노출과 (b) `saveCur` 경로가 원인입니다. 가설의 또 다른 경로인 `home` 액션은 `run.phase`가 있을 때 `saveCur`를 부르는 같은 종류의 구멍이었습니다(재현 순서에서는 phase가 없어 직접 원인은 아니었습니다). 옛 코드에서 deadrun_check.py는 설문 건너뜀 쪽 8개가 실패하고(트리 포인트 1 → 0, 이어하기 생김, 새로 고침 뒤에도 남음), 설문을 마친 쪽은 메뉴 항목만 실패합니다.

## 고침

`06a2/js/64-run-equipment.js`에 `runOver(r)`(endedAt, `sealed`, result가 lose · flee · abandon)와 `runLive()`를 두고 모든 곳이 같은 판단을 쓰게 했습니다.

- 쓰러짐 · 보스 앞 물러남 · `endRun` · 표식 도전 마침 · 포기가 확정되는 순간 `run.sealed = 1`을 붙입니다. 설문 응답과 `syncRun` · `pushRank`는 그대로입니다.
- `saveCur` · `saveBattle`은 끝난 판을 저장하지 않습니다. `home`은 기록 저장은 하되 이어하기는 저장하지 않습니다.
- `menuItems`는 끝난 판에 장비 · 깨달음 · 스킬 트리를 내지 않습니다. `equip` · `awkview` 액션도 막습니다.
- `treeCanEdit`은 끝난 판이면 거짓입니다. `trefund`에도 같은 검사를 더했습니다.
- 옛 저장본: `curSweep`이 시작할 때와 `resumeRun`에서 `G.data.cur` · `kept`의 끝난 판을 걷어 냅니다. 기록(`runs`)은 남습니다. 타이틀 · 수련장 · 기다리는 캐릭터 이어하기(`resumekept`) · `isBetween`도 `runOver`를 봅니다. 끝난 판의 플레이 시간(`playTick`)도 더 쌓지 않습니다.

## 되살아날 수 있는 경로 점검

| 경로 | 결과 |
| --- | --- |
| 쓰러짐 → 타이틀(`home`) → 스킬 트리 → 칸 열기 | 메뉴에 항목 없음, 화면을 억지로 열어도 `treeCanEdit` 거짓, `saveCur` 거부 |
| 쓰러짐 → `home` | 기록만 저장, `saveCur` 거부 |
| 메뉴 장비 · 깨달음 | 항목 없음, 액션도 거부 |
| 장비 끼우기 · 벗기 · 선택(`eqon` 등) | 모두 `saveCur`를 지나므로 거부 |
| 시험 전투 · 수련장 | 들어갈 때 `G.run`을 보관만 하고 돌려놓음. 끝난 판이면 `runOver`로 계속 끝난 판 |
| 구글 로그인 후 동기화 | `playtest/(uid)`에서 `cur`를 복구하는 코드가 없음(이름 · 해금 · 목표만 합침). 확인만 하고 고치지 않음 |
| `resumekept` | 끝난 판은 `kept`에서 걷어 내고, 현재 판 확인도 `runOver` |
| 옛 저장본의 죽은 판 | 시작할 때와 `resumeRun`에서 제거 |
| 설문 건너뛴 판이 타이틀에 남은 채 새로 고침 | 저장본이 없어 이어하기 없음 |

열린 위험: 설문을 건너뛴 판의 기록(`runs`)은 `endedAt`이 비어 있는 채로 남습니다(이전과 같음). 결과 보기의 "끝낸 판" 수에는 들어가지 않습니다.

## 시험

`python tools/deadrun_check.py [폴더]`: 가짜 Supabase로 캐릭터를 만들고 쓰러뜨려, 설문을 건너뛴 경우와 마친 경우를 비교합니다. 이어하기 버튼 없음, `G.data.cur` 비어 있음, 메뉴 항목 없음, 트리 잠김, 새로 고침 뒤, 옛 저장본 걸러 냄을 봅니다. FAIL 0이어야 합니다. 옛 코드의 index.html 경로를 인자로 주면 재현됩니다.
