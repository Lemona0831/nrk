# 모바일 브라우저 저장 실패 보완

기준일: 2026-10-13. 제보: 캐릭터 4개인데 생성·교체 시 저장 실패 안내. 제보 기기는 모바일 브라우저이며 실제 기기의 저장 자료·예외 원문은 확보하지 않았다.

## 확인과 수정

- 8칸 제한과 저장 용량은 별개다. `keepCur`·캐릭터 교체에서 나온 문구는 `saveLocal` 실패 처리였다. 슬롯 한도는 8개를 유지한다.
- 캐릭터와 누적 기록 전체를 JSON 한 개로 쓰므로 슬롯이 남아 있어도 브라우저 용량 제한에 걸릴 수 있다. 이것은 재현한 실패 경로이며 제보자의 실제 원인으로 확정하지 않는다.
- 기존 JSON을 먼저 읽고 쓴다. 쓰기에서 용량 초과 예외가 발생하면 전체 JSON을 `lz-string` 1.5.0의 UTF-16 형식으로 무손실 압축해 같은 키에 다시 쓴다. prefix는 `NRK-LZ1:`이다. 압축을 풀어 원문과 같은지 먼저 비교하고 저장 직후 실제 키 값도 확인한다.
- 실패한 쓰기 앞에서 기존 키·캐릭터·플레이 기록을 삭제하지 않는다. 기록 축약·오래된 판 삭제·다른 계정 키 정리는 하지 않는다.
- 로컬 저장 성공과 계정 추적·전송 예약 성공을 구분한다. 계정 준비 오류만으로 이미 완료된 로컬 저장을 실패로 보고하지 않는다. 계정 전송 실패는 전송 대기로 남긴다.
- 새 캐릭터와 기존 캐릭터 보관, 새 판 기록을 한 번의 저장에 함께 반영한다. 실패 시 기존 `cur`·`kept`·`runs`, 생성 중 배분과 화면을 복원한다. 재시도 때 스탯을 두 번 적용하지 않는다.
- 캐릭터 교체 실패 시 선택을 원래대로 복원한다. 실패 종류를 용량 부족/일반 실패로 나누고 상세에 단계·예외 이름·자료 크기를 표시한다. 쓰기 실패에는 재시도와 기존 전체 기록 파일 다운로드를 제공한다.
- 손상된 기존 저장을 읽지 못한 경우 빈 자료로 덮어쓰거나 계정 전송하지 않는다. 계정 전환·로그아웃도 보관 실패 시 기존 자료를 비우지 않는다.
- 자동 사이트 갱신은 JSON·압축 저장본 모두 원문 대조를 거친 뒤 진행한다.

코드: [저장](../../js/62-storage-sync.js), [압축 라이브러리](../../js/61-save-codec.js), [생성·보관](../../js/64-run-equipment.js), [입력 처리](../../js/80-events.js), [타이틀](../../js/44-screens-account.js), [자동 갱신](../../js/88-site-update.js). 공개판과 `06a2`에 같은 내용을 적용한다. 서버 세이브 형식은 바뀌지 않는다.

모바일 화면 시험의 합성 기록은 원문 6,289,264글자, 저장 77,840글자였다. 20,000개의 반복이 많은 합성 행동을 포함한 자료이므로 실제 플레이 기록의 압축률로 일반화하지 않는다. 원문·복원문은 동일했고 원본 캐릭터 4개를 유지한 채 최종 6칸을 새로고침 후 확인했다. 브라우저 페이지 오류는 0건이었다.

자료 크기 표시는 UTF-16 글자 수×2의 추정치다. 브라우저 실제 할당·다른 사이트/계정 키 사용량과 다를 수 있다. 모바일 화면을 사용하는 데스크톱 Chromium의 검사이며 실제 휴대폰의 속도·해당 계정의 결과를 확인한 것은 아니다.

## 적용 후 확인과 한계

- 제보자는 기존 자료를 지우지 않고 최신 배포를 한 번 새로고침한 뒤 생성·교체를 재시도한다. 기존 버전은 저장 실패 때문에 자동 갱신도 보류할 수 있다.
- 압축 저장을 읽으려면 이번 버전 이상이 필요하다. 이전 버전으로 되돌릴 때는 압축 저장 읽기 코드를 포함해야 한다. 다른 기기의 서버 저장은 계속 일반 JSON 구조다.
- 모든 기록이 언제까지나 저장되는 무제한 용량을 보장하지 않는다. 압축 후에도 용량·보안 오류가 나면 저장을 중단하고 기존 자료를 유지한다. 추가 실패는 상세의 단계·예외 이름과 실제 기기 자료로 확인한다.
- 이번 수정으로 제보자의 실제 기기가 해결됐다고 선언하지 않는다. 실제 생성·교체와 같은 계정의 다른 기기 이어하기 확인은 후속 확인이다.
