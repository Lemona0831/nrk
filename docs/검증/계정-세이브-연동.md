# 계정 세이브 연동 검증 (2026-10-12)

## 구현

- 구글 계정으로 로그인한 경우에만 `playtest/<uid>/saves62/<기기 ID>`에 진행 세이브를 저장한다. 익명 플레이는 기존 브라우저 저장을 유지한다.
- `cur`, `kept`의 캐릭터·장비·가방·진행 위치·전투 저장본을 그대로 저장한다. 계정이 바뀌면 기존 `accountLocal`의 분리 규칙을 유지한다.
- 슬롯마다 벡터 시계를 저장한다. 한 저장본에서 이어진 변경은 최신 후손을 반영하고, 서로 다른 기기에서 갈라진 변경은 선택 창으로 확인한다. 선택하기 전에 두 원본을 `saveBackups62`에 보관한다. 백업 실패 시 병합을 중단한다.
- 삭제는 슬롯의 삭제 기록으로 남긴다. 오래된 기기의 저장본이 자동으로 되살아나지 않는다. 삭제 이후 오래된 기기에서 다시 진행했다면 충돌로 취급한다.
- 서버에서 읽지 못하면 업로드를 시작하지 않는다. 쓰기 실패 시 브라우저 저장본과 재전송 대기를 유지한다. 온라인 복귀 시 재전송하며, 로그아웃 전 전송 실패를 알린다.
- 플레이 기록은 기존 `runs62` 목록에서 가져온다. 원격 요약 기록을 읽기만 하며 실제 전투를 재구성해 세이브로 만들지 않는다.
- 기기마다 선택한 캐릭터는 유지한다. 여러 기기의 서로 다른 캐릭터를 합쳐 8개를 넘더라도 기존 캐릭터를 버리지 않는다. 신규 생성은 기존 8칸 한도에 따른다.
- 기존 docs 어댑터의 자기 계정 하위 경로를 사용한다. 서버 실제 권한 설정은 브라우저에서 표시되는 계정 저장 결과로 확인해야 한다.

## 검증

`tools/cloud-save-browser.py`: 실제 Supabase 연결 없이 공유 메모리 서버를 사용하는 서로 분리된 PC(1280px)·모바일(390px) 브라우저 환경.

- 두 캐릭터의 PC → 모바일 이동, 공백 닉네임 유지, 원격 기록 목록 불러오기.
- 전투의 차례 7, 골드 123, 약초 2개를 그대로 복원.
- 후손 변경은 질문 없이 반영, 동시 변경은 선택 후 원본 백업·결과 반영.
- 삭제 전파와 오래된 기기에서의 부활 방지.
- 다른 계정에 세이브·기록이 나타나지 않음.
- 업로드 실패 시 로컬 골드 444 유지, 재전송 후 다른 기기에서 444 확인.
- 모바일 가로 넘침 없음, 브라우저 실행 오류 없음.

`tools/save-browser.py`: 기존 8칸 생성·보관·선택·전투 복원·실패 복구, 보스 설명·가혹 챕터 이동, 스탯·완주 화면 회귀 통과.

## 이용 및 한계

기존 캐릭터는 해당 PC에서 업데이트된 사이트에 같은 구글 계정으로 접속해야 처음 업로드된다. 타이틀에서 ‘계정 세이브 저장 완료’를 확인한 뒤 모바일에서 로그인한다. 이미 열린 기기는 타이틀의 ‘계정 세이브 새로 불러오기’를 사용한다. 전투 중 기기 이동은 저장 완료 뒤에 한다.

실제 사용자의 구글 로그인이나 세이브를 테스트 과정에서 조작하지 않았다. 충돌 원본은 서버에 남으며 별도 복구 화면은 이번 범위에 포함하지 않았다.
